# 大模型 Inference 工程实践：交给 Codex 的启动文档包

> 这是**写书项目的需求与执行规范**，不是一本已完成的书，也不是声称已经通过测试的代码包。

## 项目目标

让 Codex 在用户提供的真实环境里，**先执行、再验证、后写作**，逐章生产一本可操作、可复现、可维护的中文实战教材。整条主线使用足够小的开源模型，从模型文件走到本地生成、HTTP API、推理服务、性能测量、现成优化、部署运维；不以研究新算法、深入源码为前提。

## 文件导航与阅读顺序

1. `00_project_brief.md`：项目边界、定义、交付要求与禁止事项。
2. `01_toc.md`：全书章节、实验、能力验收与依赖关系。
3. `02_environment_and_models.md`：先探测实际硬件，再选小模型、运行时和版本的规则。
4. `03_production_spec.md`：每章的生成流程、固定结构、仓库目录与留痕机制。
5. `04_acceptance_criteria.md`：可运行、正确性、可复现、性能和文档一致性的验收细则。
6. `05_first_run_instructions.md`：**直接发给 Codex 的第一轮执行指令**；限定先交付第 0、1 章。

## 使用方式

把本 ZIP 解压到新项目目录；将 `05_first_run_instructions.md` 的正文发送给 Codex，或让 Codex 先完整阅读本目录并执行该文件。向 Codex 提供真实终端/工作区访问，并在必要时告知网络限制、允许下载与否、可用计算预算。

**不要先写整本书。** 首轮只做环境探测、选模型、构建第 0/1 章的实验、实际跑测、生成对应内容，提交测试证据与待决问题。经用户确认后再继续第 2 章。

## “100% 能跑通”的严谨定义

仅在**明确记录的环境、模型修订版、依赖版本、命令和前提条件**下，以自动检查和实测证据证明章内必选实验全数通过。不能承诺“任何机器上永远 100% 可运行”，更不能用虚构终端输出代替实测。未获硬件支持的实验可以有明确的条件性跳过（SKIP），但不能写成通过（PASS）；必要核心实验失败时，章节不得标为完成。

## 用户只需提供什么

一个 Codex 可以访问的执行环境（本地机器或租用 GPU），以及对安装依赖和下载公开模型的授权边界。不要假设用户的处理器、内存、系统或 GPU 类型。
