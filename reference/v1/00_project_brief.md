# 00｜项目任务书（Project Brief）

## 1. 定位

书名暂定：**《大模型 Inference 工程实践：从模型文件到可用服务》**。

目标读者：已有基本机器学习/编程知识，熟悉“训练结果→模型文件→加载→输入→输出”的一般概念，想掌握大语言模型推理工程的人。

学习边界：先**驾驭现有开源资源与成熟方法**，做到选择、调用、部署、测量、诊断、优化和交付；不将推导 Transformer 数学、设计新 Attention 算法、重写 CUDA Kernel、独立研发推理引擎作为必修任务。

交付对象不只是正文，还包括：可执行实验源码、命令、依赖锁定、测试脚本、验证记录、故障排查、环境/版本清单。正文和实验必须互相校验。

## 2. 成功的定义

学习者完成全书后应能在明确的软硬件边界内：

- 检查模型仓库：识别权重、配置、Tokenizer、聊天模板、格式与许可证。
- 在指定环境里运行一个小型开源语言模型，解释 Token→Prefill→Decode→输出的路径。
- 把推理能力封装为可调用 HTTP 服务，验证普通与流式响应。
- 用脚本测量 TTFT、生成速度、端到端延迟、内存/显存和吞吐量。
- 在受支持的引擎上启用量化、前缀缓存、动态批处理等**现成**功能，并记录约束与效果。
- 做好超时、并发、可观测性、部署记录和回滚，解释何时该换模型/引擎/设备。

## 3. 执行原则（必须遵循）

1. **先实测再写作**：不得先生成看似正确的命令和屏幕输出，最后补测试。
2. **真实环境决定方案**：不能把任何既往用户设备配置当作当前事实；在工作区真实探测。
3. **全书小模型贯穿**：首选可以在实际环境稳定运行、下载成本低、可公开获取并允许所需用途的模型；不追求参数规模或高分榜单。
4. **少而精，不堆工具**：核心主线选一个可运行后端；其他引擎在满足硬件条件时做可选对照，不能因此卡住主线。
5. **分层区分概念**：模型资产（权重+配置+Tokenizer 等）、模型计算结构、执行引擎、服务层、客户端、硬件不得混称。
6. **所有数字有证据**：模型大小、显存需求、速度、版本、运行结果，都必须给出来源或实际测量；未测的就标“预估”。
7. **固定运行环境**：依赖应锁版本；模型尽可能固定不可变 commit revision；记录 OS、硬件、Python/运行时及 GPU/驱动信息。
8. **每章都有验收**：最少具备从干净启动可重复执行的 smoke test 与机器可读结果。
9. **可审计的状态**：区分 `NOT_RUN / PASS / FAIL / SKIP / BLOCKED`；SKIP 必须有适用条件说明，不能充当成功。
10. **不泄漏秘密**：不得提交 API Key、访问令牌、个人文件路径、私人数据、云端凭证。

## 4. “全部可跑通”的合同定义

本项目追求：

> **在选定且记录完整的目标环境中，本章必做实验可以从已记录的前置条件出发，重复执行并通过明确断言。**

这**不代表**不同操作系统、硬件、驱动、平台上自动通用；也不意味着生成文本逐字符相同，或每次跑分完全相同。生成实验用可断言的性质（返回成功、结构正确、Token 有效、非空回复、结束标志、无异常）取代固定自然语言答案；性能实验使用统计值与观察，不用随意设定毫秒及 tokens/s 合格线。

## 5. 项目不做什么

- 不训练/微调大模型；不为了课程而先训练模型。
- 不设计新的推理算法，也不要求重写底层算子。
- 不假设一定有 NVIDIA CUDA，Mac MPS、CPU 等均可成为起点，实测后选择。
- 不承诺“13 章一次性写完且都正确”。
- 不将私有在线 API 当成本地开源推理实验的替代证明。
- 不在未经许可的情况下自动购买 GPU、部署付费资源或改变用户系统配置。

## 6. 成书标准

每章至少交付：

- **学习目标**、前置依赖和本章知识地图。
- 实际测试环境与版本矩阵（引自统一 environment lock）。
- 可照抄命令、含必要代码的独立可执行实验。
- 预期现象/结果**判定方式**（不伪造实测内容）。
- 对真实运行日志与测量值的引用。
- 常见故障、原因与排除路径。
- 对核心能力的自动化验收。
- 本章能力边界、适用/不适用情形及下一章连接。

## 7. 里程碑与停工点

- **M0 环境与模型定稿**：真实环境记录、可行的最小模型、许可证/访问检查、最小生成 smoke test。
- **M1 第 0/1 章完成**：独立完整的环境复现过程与模型资产审查实验；验收和实测证据齐全。
- **M2 第 2—4 章**：推理、采样、HTTP 服务及流式输出。
- **M3 第 5—9 章**：基准测试、资源、量化、缓存、并发。
- **M4 第 10—12 章**：引擎选型、部署稳定性、模型迁移与综合项目。

**首轮严格止步 M1。** 不得仅因章节提纲已经存在就宣布任何后续章节已完成。用户确认后再逐章推进。

## 8. 决策方式

遇到硬件能力、驱动、网络下载、模型权限、资源预算的不确定性：先检测和记录，再选择；若无法解决，给出最小替代方案与需要用户决定的事项。不要暗中换模型或引擎导致前后证据不一致。
