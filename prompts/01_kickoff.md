# 第一轮 Codex 指令（直接复制给 Codex）

你是《大模型 Inference 工程实践》项目的主实施者。请将本项目作为一个**可实测的线上交互教材**开发，而非只写文稿。先阅读 `START_HERE.md`、`AGENTS.md`、`plan/PROJECT.md`、`plan/CONTENTS.md`、`plan/MILESTONES.md`、`plan/CODEX_WORKFLOW.md`，其余规范按需读。

## 本轮只做 M0

1. 首先探测当前环境：工具可用性、系统硬件、Python、Node、Git、设备加速、剩余空间及网络状态（必要时询问安装/下载额度）。不得将历史设备配置当成事实。
2. 审核本仓库初始的 VitePress 工程。先让网站跑起来：联网时生成并提交 `package-lock.json`，使用 `npm ci`/`npm run docs:build` 和 `npm run docs:dev` 验证。检查首页、课程页面、TokenStepper 教学模拟组件的桌面/移动版。修复视觉和交互缺陷，允许适度改善设计。
3. 选小型开源自回归语言模型，核实模型仓库、许可证、不可变 revision 与引擎兼容；根据本机 CPU/MPS/CUDA 条件选择最短运行路径。获得许可后安装依赖/下载权重，真实完成 E00 环境与模型生成 smoke test。
4. 把实验源码保存至 `experiments/ch00/`，记录**真实**命令和机器可读证据至 `evidence/runs/`，并修订第 00 章，使内容与实验一致。
5. 生成实际可读的首页/章节和至少一个明确标记为教学模拟的交互示意。若图像生成或浏览器工具可用可使用，但不为调用工具而调用工具。
6. 做最小验收：实验 PASS，网站 build PASS，页面实际检查；没有条件时写 BLOCKED 和原因，绝不编造。

## 严格边界

不要写未做的第 02—12 章；不要修改用户其他项目；不擅自购买云资源、下载超预算模型、创建公开仓库或发布 GitHub Pages。无需设计复杂 agent 工作流和门禁，多留精力给代码、图像、页面、正文。

## 输出格式

报告：①已完成的具体产物；②实际运行命令和结果；③网站预览方式；④证据路径；⑤未完成项与下一轮最小任务。若 M0 成功，再建议进入 M1，但不要自动宣称全书完成。
