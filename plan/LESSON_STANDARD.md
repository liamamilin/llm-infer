# 单章交付规范（简洁可复用）

读者能通过章节完成一件事，比看起来学术完整重要。

## 每章固定八项

1. 开场：一句问题 + 完成后能做什么。
2. 概念：仅讲本实验不可缺的背景，类比传统 ML。
3. 运行前提：系统、依赖、模型 ID、commit、预计下载/磁盘开销（必须实测或注明预估）。
4. 操作步骤：从清洁环境执行，优先提供完整命令、输入、返回值形状。
5. 讲解：把发生的事与推理路径建立联系。
6. 图像或交互：有明确教学用途，不能只是装饰。
7. 自动验证：最小化 smoke/integration test；附真实 `PASS/FAIL/SKIP/BLOCKED/NOT_RUN`。
8. 故障处理 + 拓展：读者可能碰到的 2—4 个真实问题；延伸仅一到两项。

## 实验与正文保持一致

- 代码保存在 `experiments/chXX/`；章节引用真实脚本名和命令，而不是复制两份分叉代码。
- 内容中的 API 参数和输出形状须与实际执行的一致；不要使用假设性能数字。非确定性文本不要逐字硬断言。
- 记录 `python --version`、包 lock、模型 revision、OS/设备摘要、run timestamp、Git SHA。
- 性能数据至少预热 + 多轮测量，记录分布而不仅一个最好值；不同引擎/模型不能直接宣称严格公平。
- 标注纯教学模拟和实际测试，图表上的任何示例数据都必须明确来源。

## 章节文件头范例

```yaml
---
title: '第 00 章：环境与首次推理'
description: '在真实设备上跑通最小生成'
---
```

## 质量要求

汉语自然，短句为主但不浅薄；概念准确；示例可复制；不把免费/公开/可商用混为一谈。读者能够仅凭本章从零复现。
