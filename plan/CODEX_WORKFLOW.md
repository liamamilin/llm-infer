# 如何真正发挥 Codex 的能力

## 主代理 + 按需子任务，不造一个臃肿的代理工厂

主代理负责阶段目标、整合、合并代码与记录结果。**只有互不冲突的工作可以并行**：

- 工程实验：研究模型/引擎兼容性、写代码、执行、记录日志。
- 教材编辑：参考已经验证的实验，把机制和操作写清楚。
- 视觉与体验：设计图、页面和交互组件，浏览器预览、截图比较。
- 测试审阅：独立确认示例命令存在、验证通过、页面能构建、链接能打开。

不要让多个代理同时改一份同名 Markdown 或网站 config；独立任务可以使用独立工作树，合并由主代理完成。

## 可用工具的能力探测

开始时列出当前 Codex 环境**实际**可使用的工具与权限：终端、仓库操作、网络搜索、图像生成、内置浏览器、截图、子代理、GitHub API/CLI、MCP 插件、GPU/SSH。不可用则明确标记，优先用替代技术完成目标，不能伪称工具已执行。

- Web/文档：核实框架最新兼容性、模型许可、代码用法并保存链接和访问日期；公开参考不等于实验已运行。
- Browser：站点真实启动后检查桌面与移动端导航、代码块、宽表格、交互、可读性。
- Image generation：适用时为章首页生成示意性主视觉，并检查中文文字正确性；技术原理图优先 Mermaid / SVG 以便维护。
- GitHub：创建仓库、push、开启 Pages 来源为 GitHub Actions，需要明确用户授权且凭证已就绪。
- Skills：优先使用本地 `.agents/skills/lesson-production` 和 `site-visual-review` 指令；不要为了形式新增许多技能。
- CI：自动执行无硬件依赖的构建与链接校验；GPU/大模型实测保留目标设备执行记录，不强迫 GitHub hosted runner 下载大权重。

## 完成一次工作的最小报告

1. **产物**：新增/更新的章节、实验、图、页面。
2. **验证**：运行的确切命令、结果及产物路径；未运行的一定说明原因。
3. **限制**：联网、权限、资源、机型等阻塞和处置。
4. **下一步**：一个具体里程碑，不主动扩增工作流。

若你认为需要一个新流程门禁，先说明它如何防止已出现的真实失败；没有证据就先不要增加。
