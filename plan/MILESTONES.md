# 四轮里程碑：先出能看的网站，再逐步增厚教材

## M0：最小可用产品（第一轮）

- Codex 探测真实环境并保存非敏感摘要；核实下载/安装预算与权限。
- 为网站生成 `package-lock.json`；实际 `npm ci`、`npm run docs:build` 通过。
- 启动 VitePress 网站；检查首页、导航、交互示例的桌面/手机体验。
- 核实主线候选小模型与目标设备兼容性，在真实设备上成功生成 token。
- 保存实验记录；未跑的内容仍显示 `NOT_RUN`。
- 允许仅在本地完成，不需要 GitHub 发布。

## M1：能教会人的两章（第二轮）

- 完成第 00、01 章；实测命令、源码、验收数据一一对应。
- 至少 2 张讲解清楚的图/交互（不必为了画图阻塞实验）。
- 用浏览器检查阅读体验；修复阻碍读者阅读/操作的问题。

## M2：完整基础主线（第三轮起）

- 第 02—06 章，逐章实验、逐章发布。
- 至少一个实际 HTTP API + 流式响应 + 基准测试。
- 网站逐步补图，不允许先输出未经运行的“benchmark 结果”。

## M3：优化、生产、公开发布

- 07—12 章，按硬件支持实现；无法实测标为可选/硬件限定。
- 经用户授权创建/推送 GitHub 仓库、开启 Pages；验证线上链接。
- 保留长期可运行的 CI，不要求每次 CI 都重新下载 GPU 模型。

## 当前范围声明

ZIP 只提供启动脚手架和执行规范，不是假称全书已建好。Codex 应首先完成 M0，然后展示可访问的**本地**网站和真实实验，再开始下一个里程碑。
