# 项目定位与产品要求

## 终点

让已有基本编程和机器学习知识的读者，可以使用一个小开源模型，独立完成：识别模型资产 → 本地推理 → 提供 HTTP API → 流式输出 → 性能实测 → 量化、缓存、并发优化 → 部署与评估。

## 用户体验

- 用户可从「概览」「实践路线」「章节」「实验仓库」「图解」「术语」「版本与验证记录」进入。
- 学习顺序遵循问题驱动；每章回答一个问题，展示能力、可验证的命令和预期行为。
- 不把阅读变成流程审批。用简单、精准的图辅助理解；抽象内容尽可能可视化。
- 代码支持复制；实验给出运行条件、占用提示、真实输出范围、常见错误和恢复方法。
- 站点对移动端友好，中文排版清晰，可搜索；静态托管无需后端。

## 必须准确区分

- 模型权重 ≠ 模型结构实现 ≠ 推理引擎 ≠ 服务 ≠ 设备。
- Safetensors、GGUF、ONNX 的角色与兼容限制。
- Prefill、Decode、KV Cache；TTFT、TPOT、tokens/s、throughput、end-to-end latency。
- 流式输出提升体感速度，但通常不减少模型的总计算。
- 小模型可以证明流程，不代表大型模型的并行/分布式性能可以等比例外推。

## 交付分层

**必需**：可工作的站点、最小实际实验、与实验一致的正文、真实测试证据、清晰目录和 GitHub Actions 部署配置。

**增强**：SVG 动态示意、交互 token 演示、浏览器视觉回归、练习题、对照曲线、可下载实验日志、专题案例。

**以后再做**：在线云 GPU 沙箱、登录/用户进度后端、自动模型下载门户、部署成本很高的实时在线推理。

## 不做

大量研究论文复现、新算法或内核发明；多模型大排行；尚无实验支撑的“工程性能结论”；把 GitHub Pages 当成能直接运行 GPU 推理的服务器（Pages 只托管静态站点）。
