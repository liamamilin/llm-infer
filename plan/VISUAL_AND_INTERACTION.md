# 图像、动画和交互教材设计

**目标：帮助理解，不是堆视觉。** 制作技术教材时，Codex 可以处理程序绘制、插图构图、前端实现及实机截图；是否支持调用生成式图像以当前工作环境为准。

## 三种素材路线

| 路线 | 适合 | 生产与验证 |
|---|---|---|
| SVG / Mermaid | 架构、Prefill/Decode、KV Cache、调用时序 | 优先使用版本控制友好素材；内容核对过再入库 |
| Vue/SVG 交互组件 | token 选择、温度对比、缓存演示、TTFT 瀑布 | 必须标「教学模拟」或绑定真实实验数据；键盘与移动端可用 |
| Codex 图像生成（可用时） | 章节封面、隐喻式场景图、技术视觉辅助 | 提供明确 prompt；人工/浏览器检查中文、标签、无误导；记录生成来源 |

## 先做 3 张核心图

1. `资产 -> Tokenizer -> Prefill -> Decode -> API` 的推理路径图；明确概念职责。
2. `prefill vs decode` 的时间轴；体现首次处理整个上下文、后续逐 token + KV Cache。
3. `TTFT vs TPOT vs 完成时间` 的延迟剖面图。

图旁必须配文字替代说明（alt），移动端不得图太小看不清；能用矢量图表达就不把文字画到生成的位图里。

## 实交互样例

初始仓库包含 `TokenStepper.vue`，仅为**教学演示模拟**，不是真实模型运行或概率预测。它可视化“每步选择一个 token”的过程。第一轮优先检查它在本地站点是否正常工作并优化视觉，而非立即做耗费 GPU 的网页实时推理。

## 图像生成任务单格式

- 教学目标：读完图读者应该弄懂什么。
- 内容必须包含：例如「输入 Token」「Prefill」「Decode」「KV Cache」。
- 内容不能包含：伪造的实验曲线、虚假的硬件测试截图。
- 风格：教学型、简洁、不夸张；不要满屏装饰。
- 输出：源文件和 Web 优化格式；验收：含义准确、文字清楚、响应式。

> 初始网站已提供静态 SVG 推理流程图；如要在站点直接嵌入 Mermaid 源码，请由 Codex 配置并验证 Mermaid 渲染插件，避免把代码块当作已完成图像。
