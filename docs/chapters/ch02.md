提示词 `The capital of France is` 被切成 5 个 token：`The`、` capital`、` of`、` France`、` is`。实测输出（节选）：

```text
step 0 [prefill] in= 5 cache_before= 0 -> ' Paris' p=0.4693 top3=[(' Paris', 0.4693), (' the', 0.2657), (' located', 0.0831)]
step 1 [decode ] in= 1 cache_before= 5 -> '.'      p=0.5389
step 2 [decode ] in= 1 cache_before= 6 -> ' Paris' p=0.3909
...
step 7 [decode ] in= 1 cache_before=11 -> ' in'    p=0.9345
manual == generate(): True
```

## 两个阶段

| | Prefill | Decode |
|---|---|---|
| 做什么 | 一次前向处理**整段 prompt**，产出第一个新 token | 每步只喂**上一个新 token**，产出下一个 |
| 本例输入长度 | 5 个 token | 1 个 token |
| 计算特点 | 并行处理多个位置，吞吐高 | 一步依赖上一步，只能串行 |
| 影响的指标 | TTFT（首 token 延迟） | TPOT（每 token 间隔） |

Decode 之所以每步只喂 1 个 token，是因为前面所有 token 的 Key/Value 已经存进 **KV Cache**。实测缓存长度从 5 开始，每步 +1，8 步后是 12（5 个 prompt + 7 个已解码输入；最后一个新 token 还没被喂回模型）。第 06 章会量化它。

## 每一步其实只做一件事

模型输出的是对整个词表（49152 项）的打分，经 softmax 变成概率。上面 `p=0.4693` 就是 `Paris` 的概率；本章用**贪心**选概率最大的那个。如何用别的规则选，是下一章的内容。

## 验证了什么

脚本断言了四件事，全部通过：手写循环与 `generate()` 输出完全一致；Prefill 一次吃下整个 prompt；Decode 每步只喂 1 个 token；缓存长度等于 prompt 加已解码输入数。

## 小结

推理 = 1 次 Prefill + N−1 次 Decode，每次都是"打分 → 选一个 → 追加"。后面的流式、基准、缓存、批处理，都是在这个循环上做文章。
