# 第 00 章：环境与首次推理

> **状态：PASS**（Apple M4 Pro / MPS / Python 3.12 实测）。证据：[`ch00-smoke.json`](https://github.com/liamamilin/llm-infer/blob/main/evidence/public/ch00-smoke.json)。其他设备请按下文自行运行，结果以你机器上的输出为准。

## 这一章要做成什么

在不依赖云端 API 的前提下，把一个真实模型加载到本机并让它续写文字，再确认结果是可重复的。

## 全书主线模型

| 项 | 值 |
|---|---|
| 模型 | `HuggingFaceTB/SmolLM2-135M-Instruct` |
| 固定 revision | `12fd25f77366fa6b3b4b768ec3050bf629380bac` |
| 许可证 | Apache-2.0 |
| 参数量 | 约 1.35 亿（第 01 章实测 134,515,008） |
| 下载体积 | 约 270 MB（只拉 8 个必要文件，不含 onnx） |

选它是因为小：笔记本 CPU 也能跑，几秒就能验证一条流程。它的回答质量很一般，**本书用它证明流程，不是比较模型能力**。

## 动手：5 分钟

需要 Python 3.10+（本书用 3.12）。在仓库根目录：

```bash
python3 -m venv .venv
```

```bash
.venv/bin/pip install -r requirements.txt
```

```bash
.venv/bin/python -m experiments.ch00.smoke
```

第一次运行会下载模型到 `models/`（已被 git 忽略）。我们这台机器上的输出：

```text
device=mps load=0.47s generate=0.15s
prompt='The capital of France is'
new_ids=[7042, 30, 7042, 314, 260, 3995, 2240, 281]
continuation=' Paris. Paris is the largest city in'
PASS
```

脚本会按 `mps → cuda → cpu` 的顺序选设备；在没有 GPU 的机器上走 CPU，更慢但结果同样有效。生成使用贪心解码（`do_sample=False`），所以相同设备和版本下输出是确定的。不同设备的浮点实现略有差异，个别 token 可能不同，这是正常的。

## 发生了什么

1. `ensure_model()` 按固定 revision 下载文件，保证每位读者拿到同一份权重。
2. `AutoTokenizer` 把字符串切成 token id，`AutoModelForCausalLM` 把权重装进 PyTorch 的 Llama 结构实现里。
3. `generate` 反复做"预测下一个 token → 追加 → 再预测"，一共 8 次，得到 `new_ids`。
4. `tok.decode` 把 id 变回文字。

这就是后面所有章节的起点：之后的流式输出、基准、缓存，都是在这条路径上做文章。

## 常见问题

- **下载很慢或失败**：设置镜像或代理后重试；脚本会续传，已下载的文件会跳过。
- **`mps` 报算子不支持**：运行前设置 `PYTORCH_ENABLE_MPS_FALLBACK=1`，或临时改用 CPU。
- **`generate` 的时间是否能当性能数据？** 不能。这里只有 1 次、8 个 token、没有预热。严肃测量留到第 05 章。

## 小结

你现在有一个固定版本、可重复运行的本地模型。下一章拆开它的文件，看看"模型"到底由什么组成。
